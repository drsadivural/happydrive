# 初期データ移行手順

既存の配送先リストや発注企業・拠点を HappyDrive に取り込む手順です。本番データの移行は必ずステージングで同じ手順を一度実施してから行います。

## 1. 発注企業・拠点
1. 企業担当者に Web ポータルでアカウント作成と企業登録をしてもらう（利用規約への同意と MFA 登録を本人が行うため、運営による代理作成はしない）。
2. 運営が書類を確認して「承認」。
3. 拠点は企業ポータル「拠点」で登録（住所と緯度経度）。多数ある場合は `POST /v1/organizations/{id}/sites` を担当者の認証で呼ぶスクリプトを用い、`Idempotency-Key` に元データの行IDを使って再実行しても重複しないようにする。

## 2. ドライバー
- 電話番号の本人確認と規約同意は本人がアプリで行う必要があるため、一括登録は行わない。既存の協力ドライバーには案内文（アプリ入手→電話番号→本人情報→書類提出）を送付する。
- 保有資格は本人が資格証を提出し、運営が確認する（`/me/skills` → 運営Web）。

## 3. 配送先（ドライバーごと）
- アプリの「CSV取込」を使う。列: `address`（必須）, `latitude`, `longitude`, `time_start`, `time_end`, `priority`, `service_minutes`, `recipient_name`, `recipient_phone`, `package_number`, `note`（UTF-8、ヘッダ行必須、500行まで）。
- まず「確認のみ（dryRun）」で重複・エラー行を確認し、修正後に取り込む。緯度経度のない行は「住所未確定」となり、端末で住所候補を確定するまでルート計算に含められない。

## 4. 検証
- 取込件数・エラー件数を記録し、`GET /v1/admin/audit-events?entityType=user` で `stops_imported` イベントを確認。
- 移行後の最初の締め日に `GET /v1/admin/reconciliation` で差異0を確認。
