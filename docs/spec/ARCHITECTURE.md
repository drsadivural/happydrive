# システム設計

## 要件 → 構成 → 実装 → 検証 → 配備
iPhone SwiftUI (iOS 17以降、最終対応範囲はビルド時に決定) ⇄ HTTPS API (Fastify/TypeScript) ⇄ PostgreSQL 16 + PostGIS / Redis。APIからジョブキューを通じて通知(APNs)、メール/SMS、決済/振込、証跡保存に接続。企業/運営向けNext.js Webは同じAPIでロール別に認可。実店舗/訪問サービスの決済はAppleの物理サービス規則に従い外部決済を利用。決済/振込先の契約主体、必要な規制対応は事業者決定後に確定する。

## サービス境界
`identity` 登録・電話確認・KYC状態・端末/session・RBAC; `delivery` 停止地点・ルート・証跡; `jobs` 発注/予約/受諾/実行/検収; `matching` ハードフィルタ・説明可能な順位; `location` 一時位置/チェックイン/保持期限; `payments` 請求・台帳・Webhook・振込/照合; `messaging` 案件チャット/通報; `learning` 教材/資格; `admin` 審査/紛争/監査; `notifications` APNs/メール。最初はモジュール分離した単一API、独立DBのマイクロサービス化はしない。

## データと整合性
PostgreSQL/PostGISでユーザー/組織/案件/受諾/配送/報酬を保持。発注の最終枠は `SELECT ... FOR UPDATE`、予約テーブル一意制約、受諾APIの冪等キーとoutboxイベントで保証。外部Webhookは署名検証・イベントID一意・再試行/重複耐性。証跡のメタデータはDB、実ファイルは暗号化オブジェクトストレージで有効期限付き署名URL。端末はKeychainトークンと暗号化済み最小キャッシュ。PIIの削除・保管ポリシーを対象データごとに定義。

## 地図・位置・経路
MapKit表示、Appleの経路案内、Core Locationを使用。複数停止地点最適化はサーバーの移動時間行列＋制約付きルーティングエンジン（例 OR-Tools）で実装し、運用地域・費用・利用規約に適合する行列プロバイダを選定する。MapKitの二点経路APIだけで多数地点の最適化を実現したと宣言しない。距離が概算/道路所要時間が未取得なら明示。通常はWhen In Use位置権限。バックグラウンド追跡は具体的業務が必須と判断された場合に個別実装・説明・電池/停止/拒否テストを追加する。

## セキュリティとプライバシー
TLS、短命アクセストークンとローテーションするリフレッシュトークン、メール/電話OTPレート制限、発注者MFA、最小権限、組織ID境界、管理操作の監査。APIの認可はすべてリソース所有権を検査。不要な位置連続保存を禁止し、案件実行中のサンプルを必要十分に制限。高齢者・健康関連の個人情報は目的を限定しアクセス監査/保存期限/削除/インシデント手順を備える。ユーザーからの開示/削除申請を受け付け、支払・紛争の法的保管例外を説明。

## 支払い
受諾前の表示は総額・費用負担・手数料・支払予定日を確定版としてスナップショット保存。検収完了時に台帳エントリ作成、返金/差戻しは逆仕訳。Webhookのみを入金成立の根拠にせず、決済事業者の決済IDを照合。二重振込防止キー、失敗時の再試行、月次照合を実装。事業者契約なしの本番送金機能は公開しない。

## 観測・運用
構造化ログにrequest_id/job_id/actor_id（氏名・住所・トークンは除外）、メトリクス（受諾競合/決済失敗/通知失敗/ルート失敗）、分散トレース、運営アラート、障害手順。DBバックアップ/復旧演習、CIでlint/typecheck/unit/integration/e2e/security scan、ステージングでAPNsと決済サンドボックス。CloudflareはDNS/WAF/静的Web、状態付きAPIとDBは運用実績のある日本リージョンのマネージド基盤を推奨。各社を契約前に比較する。

## 外部接続の契約ゲート
ZENRINやLocationMind等の正式利用、住民/医療情報連携、企業ロゴ表示、決済/本人確認SDKには契約・利用規約・データ処理契約・料金・障害/レート制限・テスト環境確認が必要。パートナー未確定でも自社案件による縦断フローは完成させる。
