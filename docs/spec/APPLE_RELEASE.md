# Apple提出・運用ゲート

## 提出前に用意するもの
権利者提供のHappyDriveロゴ原本（ベクター/高解像度、利用許諾）、法人Apple Developerアカウント、Bundle ID、署名、APNs鍵、公開の利用規約/プライバシーポリシー/サポートURL、発注/報酬の契約条件、Apple審査用の稼働したドライバー/発注者デモアカウントとサンプル案件、問合せ窓口、本番決済/本人確認事業者契約。アカウント削除はアプリ内から到達可能にし、審査アカウントにOTPの突破方法を記載。

## iOS実装点検
- `ja-JP` 全画面、権限文、失敗文、VoiceOverラベル、通知文、ストア掲載文を確認。意味のない英文・ダミーデータ・未実装ボタンなし。
- 位置の`NSLocationWhenInUseUsageDescription`、カメラ/写真/通知の利用理由を実際の機能に合わせる。バックグラウンド位置を使う設計ならUIBackgroundModesと適切な説明・停止動作を別途審査する。
- サードパーティログインを追加するならAppleの同等ログイン要件を再確認。電話OTPだけで進める初版は対象外かを提出時に判定。
- プライバシーマニフェスト/必須理由API/全SDK署名・収集データ/第三者共有とApp Store Connectのプライバシー回答を照合。
- アプリ内の業務委託/物理サービス代金にStoreKitを誤適用しない。デジタル教材や追加サブスクリプションを有料販売する場合は別途課金規則を確認。
- 人の通報・ユーザー投稿・チャットの不適切コンテンツ対策（ブロック、通報、対応窓口）を設ける。
- アイコンは提供ロゴの正式マスターから1024px非透明で作成。モック画像やフレーム付き画像をそのままアイコンにしない。ストア画像は正式ビルドの実画面から対応サイズで取得。

## 審査用メタデータ
アプリ名候補: 「HappyDrive｜配達と地域の仕事」。サブタイトル候補: 「配送ルートと近くの案件をひとつに」。説明文は配達先登録/経路/完了と公開済み案件/受諾/報酬を正確に記載。年齢区分、権利、コンテンツ、暗号化申告、位置データ、トラッキング、プライバシーポリシーを実際のビルドから申告。

## TestFlight → 提出基準
実端末2機種以上、古い対応iOS版と最新iOS版、位置拒否/低精度、ネットワーク断、通知拒否、低電力、ダークモード、大きい文字、VoiceOver、スナップショットと実際の表示が一致すること。クラッシュ0、P0/P1バグ0、入金/受諾/削除の高リスク試験合格。審査用手順書に動作可能な権限/業務データと必要なテスト操作を明記。Appleの最新のスクリーンショット仕様は[公式仕様](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications)で提出日に再確認。

審査に通るかはAppleが判断する。パッケージ単体の完成によって提出可能性や審査通過を保証しない。
